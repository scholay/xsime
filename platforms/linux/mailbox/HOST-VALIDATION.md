## Native UI contract

The AppKit exporter renders the actual production workspace, with isolated records and plugin preferences. It verifies the three real hash-pinned bundled packages before rendering. Updating Linux declarations also regenerates the macOS catalog projection; stale package hashes would otherwise silently disable native filtering in a fixture.

Native `MailboxUI` constants supply dimensions; exported NSColors supply four theme palettes, and real module declarations supply labels, icons and filters. Linux's build checks the complete source SHA-256 map and matching behavior/UI exports before compiling the workspace. This gate detects drift; it is not a pixel-equality assertion.

[24 matched production renders and their differences](../../../validation/linux-mailbox-host-20261018/README.md) cover terminal/chat/inbox × four themes × 1000×700 or 680×500 at 2×, timezone Asia/Tokyo. Row and heading line metrics, sidebar/note/composer backgrounds and badge contrast were adjusted against AppKit. All pages remain `requires_review`: fonts, icons, search/segment controls, body paragraph spacing, missing inbox actions/Markdown/PTY content and hovered/focused/error/active states still need the corresponding implementation and visual acceptance. Offscreen AppKit rendering and private X11 windows do not prove physical GNOME/KDE/Wayland lock, multi-monitor, scaling or assistive-technology behavior.
