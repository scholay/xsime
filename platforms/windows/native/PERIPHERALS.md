# Windows Capsule / Mailbox 开发预览

开发基线：`823c910` / Windows 1.1.5。本次把 Capsule、Mailbox 和 Buffer 暂存接入
同一个 Broker，不新增 TSF 协议或网络监听端口。Windows 原生前端已按当前 macOS 源码重做主要布局，
**尚未完成全部 macOS 功能对等，也不是发布或安装记录**。

## 当前界面契约（2026-10-17）

### 宿主、插件与窗口角色

`Buffer`、`Mailbox`、`Capsule` 是同级核心宿主，共用输入法 Broker 的进程生命周期；
窗口关闭、设置导航或某个插件停用，不构成另一个宿主的所有权或自动投递权限。
设置导航沿用 macOS `SettingsRouting.swift` 的核心顺序，三个宿主不属于“扩展”。
插件管理按 `buffer` / `capsule` / `mailbox` / `extension` 分类；Capsule 和 Mailbox
模块通过原宿主暴露插件描述及启停入口，设置与宿主菜单共用既有持久化状态。停用同步
撤销该模块的借用输入与生成权限，保留内容。分页覆盖全部已接入插件，不依赖固定四行截断。

macOS 三个内置扩展的身份为并击 `builtin.fly-chord-learning`、打字测速 `builtin.typing-speed`、统计 `builtin.statistics`。当前 Windows 三者均已接入；测速与统计的实现、存储和验证边界见 `METRICS.md`。不得再沿用“测速与统计尚未移植”的旧交接描述。

| 表面 | macOS | Windows 对应角色 |
| --- | --- | --- |
| Buffer | `.nonactivatingPanel` 的浮动 `NSPanel` | `WS_POPUP` + `WS_EX_TOOLWINDOW` + `WS_EX_NOACTIVATE` + `WS_EX_TOPMOST` |
| Capsule 底栏 | 浮动 `ClipboardHistoryPanel : NSPanel` | 同上；无借用目标时唤出即聚焦搜索，但仍浮动 |
| Capsule 管理/编辑 | 普通可获焦 `NSWindow` | 可获焦顶级 HWND，普通 Z-order；从底栏切换时用 `SetWindowPos(HWND_NOTOPMOST)` 移出置顶层 |
| Mailbox | 普通可获焦 `NSWindow` | `WS_OVERLAPPEDWINDOW` + `WS_EX_APPWINDOW`，普通 Z-order |

Buffer 不再因设置窗口仍存在而取消置顶，也不再拦截 Z-order 请求把自己放到设置后面。
Capsule 的角色切换保留其他扩展样式，置顶层通过 `SetWindowPos` 改变，避免搜索或返回底栏
时覆盖 `GWL_EXSTYLE` 丢失置顶属性。显示与置顶都不授予 TSF 插入权限。
`WS_EX_TOOLWINDOW` 本身不保证置顶；`WS_EX_TOPMOST` 保证高于普通窗口，与“不抢焦点”独立。
参见微软 [窗口扩展样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)
和 [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

尺寸以 **client area 的 DIP** 为准，不把 Windows 标题栏计入 macOS 内容尺寸。
参照 `ClipboardRailView.swift`、`CapsuleWindowController.swift` 和 `Mailbox/` 当前代码，
而不是历史文档里的尺寸：

- Capsule：底栏 940×208，卡片 206×126、间隔 8，左侧筛选列 60；双击笔记/密码
  在相同卡片区域内查看，方向键选行，Esc 先返回；管理页 940×660（最小 620×430），
  编辑页 460×400（最小 360×300）。管理/底栏切换以窗口底边为锚点。
  底栏使用 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`，通过同一精确 TSF 会话借用 Rime 搜索输入；方向键选卡片、
  Tab 切换筛选、Ctrl+A/C/V/F/N 与 Esc 均按当前逻辑输入归属处理。Enter 的文字插入复用
  原有 TSF 投递与确认通道，不占用或消耗 Buffer；目标变化撤销租约。没有可借用输入框时，
  唤出即聚焦 Capsule 原生搜索，普通卡片 Enter 只复制关闭。管理和编辑页正常取得焦点。
  可见图片卡片使用有界后台缩略图与最多 32 项缓存；密码验证从相同租约读取物理字母批次。
- Mailbox：1000×700、最小 680×500，左导航 64、按钮 48×56、会话行 84、动作 28；
  列表 216/232/200，终端扩展区 240；窄窗口用带遮罩抽屉覆盖正文，原生正文/PTY 尺寸保持稳定。
  对话 Enter 发送，Shift+Enter 换行，中文 marked composition 的 Enter 仍交给 IME。
  阅读区由逐消息组件组成：身份/时间、可选择正文、user 整块背景、流式单消息更新；
  接收消息有独立复制/加入 Buffer/存入 Capsule，图片有打开/保存，待处理收件有忽略。
  显示层支持标题、粗斜体、代码、列表/勾选项、引用、制表位表格、HTTP(S)/mailto 链接、JSON；
  保存和复制保留原文。刷新保留文字选择和阅读位置，接近底部且无选区时跟随新消息。
- Mailbox、Capsule、Buffer 跟随四套产品主题。控件保留原生文本编辑、键盘焦点和剪贴板
  选择能力；控件图标统一使用随包附带的 Fluent System Icons。
- Buffer 以当前 `BufferWindowController.swift` 为准：工具栏 **30**、普通总高 **73**、
  双轨总高 **105**、默认宽 **760**；翻译正文内部上下留 5，双轨各 25、间隔 4。
  旧文档中 33/78/112 的描述已不是当前实现。已有用户自定义宽度继续保留。

布局更新不再先隐藏全部原生控件，避免在重排时撤销正在进行的 IME 组字。

密码复制设置剪贴板历史/云同步排除标记和监视排除格式。普通编辑控件的复制/剪切也
经过此路径。60 秒后仅在剪贴板序列未变时清除；退出和保护态提前清除。
默认四组口令为 `RH / WO / CVN / QU`；自定义凭据只保存 24-byte 盐和 SHA-256 摘要，
损坏时不回退到公开默认。密码标题为明文，正文不参与搜索。
Windows DPAPI 格式与 macOS 密码格式不同，不能直接搬移其密钥或密码目录。

## 数据与权限

数据位于 `%LOCALAPPDATA%\RIMES\peripherals-v1`：

- `records/<uuid>.json`：每条记录的权威版本，预期 revision 校验后原子替换。
- `assets/`：独立托管附件；历史清理回收无引用资产，绝不递归删除资源目录或用户原始文件。
- `preferences.json`：模块启停、剪贴板开关、窗口尺寸、Capsule 和 Mailbox 各自上次打开的模块。
- `reveal-credential.json`：本机查看口令凭据。

目录 ACL 只允许所属用户和 SYSTEM，拒绝重解析点。损坏单条文件不隐藏整个库。
同一 Windows 用户权限下的恶意进程不在密码防护范围内。

Capsule 首次通用唤出打开 macOS 的“最近”（界面显示为“临时”剪贴板历史），之后
恢复上次成功打开的模块，重启后也保留；快捷键、托盘及管理入口共用此偏好。
失效或停用的模块回退到“临时”，若“临时”也停用则使用首个启用模块；全部停用时
不打开，也不自动启用任何模块。仅记住模块 ID，不恢复密码查看授权，Mailbox 不改写此偏好。

Mailbox 首次通用唤出默认“对话”，之后恢复上次成功打开的“对话／收件／终端”模块，
重启后仍保留，与 Capsule 的选择互不覆盖。失效或停用的选择先回退“对话”，再选择
首个可用模块；全部停用时不打开。恢复终端页不会自动启动终端进程。

Capsule 卡片悬停仅在目标卡片变化时重绘旧、新两张卡片，不先擦除背景；卡片和复制
图标在内存中完成绘制后一次呈现。空白、卡片间隙及过期的离开事件不触发整栏刷新。

### 唤出、取消与自动清理（2026-10-18）

快捷栏唤出后立即进入搜索和导航：有可信目标则借用精确 TSF 输入，保持非激活；否则直接
聚焦本机搜索。只有快捷栏可见时观察鼠标按下，外部点击（包括原目标输入框）异步取消、
释放借用输入并隐藏，原点击继续交给目标应用。卡片、子控件和所属弹出窗口不误关闭；
旧一轮排队的点击不能取消下一轮唤出。管理/编辑窗口保留普通窗口及未保存内容保护。
观察回调不读写文件或吞鼠标事件，遵循
[LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc) 的短回调要求。

记录开关仅放在“设置 → Capsule”，默认开启、立即持久化。恢复建立当前剪贴板基线，
不补收暂停期间的内容；快捷栏与菜单不再放置此开关。

清理在启动、每小时和新内容收录时执行。临时历史保留现有 200 条上限并增加 1 GiB 总容量
上限，按最近使用顺序淘汰末尾条目，参考 macOS `ClipboardHistoryModel.trimToBounds`。
这里采用适合当前 Windows 历史规模的容量，不照搬 macOS 的 100,000 条/64 GiB 默认值。
新自动截图记录 `temporaryCapture` 与原始 `captured`，按 macOS `CaptureStore` 的
30 天/10 GiB 规则回收；卡片菜单可“永久保留”。收藏、手动导入、旧版未标记来源的捕获
不作自动过期推断。编辑和堆栈正在使用的记录、Capsule 当前卡片与仍在剪贴板中的附件
延迟清理，后续维护时重试。

删除前扫描所有模块（包括停用模块）的引用，保护共享附件、截图编辑源图与保存路径。
清理记录后同步删除无引用的托管文件；遗留孤立文件至少经过一小时宽限再回收。
重解析路径拒绝处理，损坏记录导致本轮清理在删除前停止，并阻止继续自动收录造成无界增长。
不会遍历/删除用户原始资源或外部目录；被其他进程占用的文件保留后续重试。

### 剪贴板卡片使用与排序（2026-10-18）

对照 macOS `ClipboardHistoryWindowController`、`ClipboardAutoPaste`、
`ClipboardCopyToast` 和 `ClipboardHistoryStore`：

- “临时／最近”双击卡片与 Enter 共用使用动作。文字沿用精确 TSF 投递并等待确认；图片
  写入 PNG + CF_DIB 后关闭 Capsule，等待至少 50 ms 再发送一次原生 Ctrl+V。此例外只用于
  显式图片使用，不作为普通文字上屏的回退。图片由目标应用自身处理；不支持图片的输入框
  可能忽略它，系统没有通用接口确认图片已被该应用接收，提示因此只说“已发送图片粘贴”。
- 图片使用要求原有精确 TSF 会话仍有效、原前台窗口和原焦点 HWND 未变、剪贴板序列未变、
  无未决组字/投递、交互桌面有效且快捷键与鼠标键已松开。关闭后最多等 900 ms；超时、
  切换输入框后再回来、重新打开 Capsule 或锁屏均撤销请求。绝不恢复/强抢外部焦点；
  没有可信目标时只复制，显示“请在目标输入框粘贴”。SendInput 被完整性边界阻止时同样降级，
  不重试可能已部分发送的粘贴。参见微软
  [SendInput](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput)。
- 复制按钮/Ctrl+C 只复制对应卡片内容，成功后关闭 Capsule，在屏幕下部显示约 1.4 秒的
  主题小字提示；提示不激活、不接收点击、不包含正文。失败保持窗口可见。密码仍遵守验证、
  排除历史/云剪贴板与 60 秒清理规则，不自动粘贴。Mailbox 原有复制行为不变。
- 临时历史按最后复制/使用时间倒序、原捕获时间倒序、ID 升序排列。重复文本或同格式同字节
  媒体/文件提升原卡片，跨间隔条目和重启去重；旧无指纹附件也可匹配。使用后只写 `promoted`
  与 revision，不改原 `updated` 时间。保存的各模块仍按更新时间倒序、ID 升序，复制不改变
  保存时间。自身剪贴板写入更新观察基线，不重复收录，也不把收藏内容重新加入临时历史。
- 原生 UI 回归使用隔离存储、假剪贴板与假输入发送器，覆盖关闭/提示、延迟、取消、去重和
  排序；不向用户应用真正粘贴。真实目标应用接受图片仍属于人工宿主验收。

收件备注不调用 AI；只有“对话”的明确发送才调用已启用连接器。
流式半成品仅在内存中，成功且权限仍有效才保存。改变默认连接器不会改变旧对话；
修改或移除原连接配置则要求恢复配置或新建。外部收件暂存前显示内容确认；
文字仍由既有 TSF 通道交付；显式图片使用的原生粘贴例外见上文。

## 2026-10-17 功能核查与补齐

截图现在走 Broker 内的原生框选，不再把“打开系统截图工具、等待手工导入”描述为完整截图功能。

- `Alt+Shift+4` 或 Capsule 相机按钮开始框选。Esc、失焦、显示器配置变化取消；松开鼠标后按物理像素保存 PNG，进入捕获历史及所选屏幕的左下角堆栈。热键注册失败有明确提示，不显示虚假的成功状态。
- 堆栈支持复制图片、编辑、另存 PNG、关闭卡片和翻页；关闭或复制后移除卡片不会删除历史。编辑支持箭头、矩形、画笔、实心遮盖、裁剪、撤销和重做；保存采用 revision 校验，保留原图与编辑步骤，重新打开仍可撤销。复制和导出仅含当前渲染像素。

### Buffer 默认状态与生命周期核查（2026-10-17）

本轮对照 macOS 的 `BufferWindowController.swift`、`BufferAutoSendClock.swift`、
`PluginPlatform.swift` 和 `RIMESController.swift` 源码，未做 macOS 真机并排验收。

- 首次使用选择“Default”，显式唤出恢复上次仍可用的插件；选择“Default”也会记忆，禁用/卸载会回退。仅保存插件 ID，不保存草稿、结果、目标输入框或唤出状态。
- 关闭暂停处理并保留本进程草稿；重开从当前有效输入框重新绑定。组字中的关闭/切换请求交给原 TSF 会话，通过 Rime 确认后暂存，随后完成动作；焦点变化、内容变化、超时和旧 DLL 未响应时不猜测组字内容，不向目标应用插入文字。
- 结果按插件分别保留，切回恢复；共享原文变化后丢弃过期可变结果，已交付原文对应的剩余译文继续保留。插件或连接器授权失效后不可恢复相应结果。草稿和这些缓存只存在内存中。

### Capsule 内部导航与高 DPI 点击（2026-10-23）

低级鼠标钩子的回调可能使用进程默认的 DPI 上下文，而 Capsule 使用线程 PMv2。
在回调中直接命中测试会把高 DPI 屏幕上的内部标签误判为外部点击。
现在只在物理坐标命中测试期间切换到 PMv2，随后恢复回调上下文；内部控件与拥有的弹出菜单保持打开，真正的外部点击仍取消操作并继续传递给目标窗口。

后续原生回归还捕获到首次内部点击期间 `WM_ACTIVATE/WA_INACTIVE` 的目标句柄与前台窗口短暂为空：鼠标按下/松开均命中自己的标签，空失活目标却排队取消了面板。空失活句柄不再被当作已知外部窗口；有效外部失活目标和物理外点仍按原取消流程处理。回归同时覆盖这一瞬时状态和继续完成内部导航。

`RimesPeripheralTests --capsule-navigation` 检查五个模块、各模块左侧分类、首尾切换、卡片结果与原输入租约，并检查从 DPI unaware 上下文调用命中测试后恢复原上下文。
`--capsule-navigation-native` 额外保留进程默认 DPI 上下文、仅把 UI 线程设为 PMv2，以真实鼠标输入覆盖钩子及外点取消；每次点击临时限制指针在测试控件内，确认带标记的按下/松开完成后恢复限制，退出恢复鼠标位置。测试采用与生产一致的整个线程消息队列，避免按窗口过滤消息导致重排。该测试需交互桌面，应串行运行。
原生模式已在 150% 缩放下验证。借用输入使用隔离的合成 TSF 租约，不能代替所有外部应用或混合 DPI 多屏的人工验收。

本轮同时修正图片卡片菜单：有有效目标时允许现有图片粘贴流程，文件自动粘贴仍禁用；设置中的长按默认时长说明改为与实际行为一致的 0.6 秒。上方历史核查条目仅记录各轮当时状态，不应视为当前未完成清单。

### Default 与 AI 流式交互（2026-10-17）

Default 增加常驻 16 DIP 实时测速行（字/分、码长、击键/秒、回删）；6 秒空闲后开始新输入段，不统计粘贴、重复按键与生成文字。右侧为 N/1/2/3/5 倒计时与 26×15 自动关闭开关，移除冗余更多入口。ChatGPT 的模型和推理深度按请求冻结，生成期间调整只作用于下一次。

ChatGPT 改用独立 Codex app-server：先完成 initialize/空 MCP 检查，再核验实际模型，随后提交输入。正文 delta、公开思考摘要与阶段提示分别更新；原始推理链不进入 UI 或结果。API 的 SSE 正文同样增量入栈；仅服务提供明确公开摘要时展示摘要，其余推理事件显示“模型正在思考”。

流式块按 macOS 的语义规则拆分：短句/分句、四个英语单词、48 字符，保护网址、数字、引号、代码与字素，过多块均衡压缩至 200 个。未完成块不可发送/复制；成功完成后保留块编号，失败、停止和切换清除当前未完成输出，之前完成的插件结果仍按生命周期规则保留。思考摘要位于独立行，悬停可查看完整公开摘要。
