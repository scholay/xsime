# iOS 1.1.9 (65) Keychain repair

The maintainer authorized this iOS-only update for the App Store and TestFlight.
Other platform versions remain 1.1.8. Existing bundle identifiers, shared groups,
user data, store territories, pricing and automatic release settings stay intact.

The fix is merged in `9ed518bab8a43104469036f71ea901e99bc894d1` (PR #276).
It preserves `585J2TL9U6.org.scholay.rimes.ios.shared` through unsigned builds
and validates the packaged runtime group against actual signing permissions.
See the [investigation](../../../../validation/ios-keychain-20261023/README.md).

Release preparation reads the iOS version from `project.yml`, rather than the
desktop `VERSION` anchor. The tag, generated Xcode project and release notes
must agree with that iOS version. The archive workflow retains the exact source
commit and ZIP digest; cloud signing uses the existing authorized Apple account.

At preparation time, App Store Connect reports 1.1.8 (64) Ready for Distribution
and TestFlight Testing in the existing RIMES Community group. Build 65 has not
been uploaded. The existing 1.1.9 draft contains localized repair notes and no
selected build. Neither comparison IPA from the investigation is a release input.

Acceptance still requires a new-source CI archive, a verified distribution IPA,
Apple processing readback, and separate App Store and external TestFlight review
submissions. Physical-device acceptance has not been performed. A green CI run,
an exported IPA or a successful upload alone is not evidence of store availability.
