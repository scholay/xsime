# 验收资料存放规则

本规则适用于根目录和各平台的 `validation/`。验收截图、对比图、重复截图和原始日志不再进入 Git；本地已有附件保留原路径，后续生成的附件保留在本地或对应 CI 的构建产物中。

仓库继续保存可审查的文字结论、复现步骤、源码与构建版本、来源记录、校验和、对照清单、聚合统计、几何读数和复现脚本。应用图标、运行时图片、商店展示素材及产品测试所需的 `tests/fixtures/` 不属于验收附件。

## 哪些内容不提交

- 验收原图、裁剪图、并排图、差异图及重复副本。
- `.log` 和轮转/压缩日志、控制台 `.txt`、事件流，以及包含原始输出的 CTest XML。
- 逐帧原始诊断采样；结构化报告中也不嵌入 `stdout` / `stderr` 日志正文。

结论使用 Markdown，聚合结果使用 JSON；文本校验和与已有结构化概要仍可保留。需要记录原始日志来源时，只记录附件路径、字节数、SHA-256 和实际存放位置。不要为了提交附件改扩展名或使用 `git add -f`。

## 阅读历史记录

历史文档、HTML 图库和清单中的图片或日志相对路径指向本地附件。干净检出不会包含这些文件，也不表示历史验收从未执行；历史结论同样不代表当前构建或当前机器已经通过验收。

查看原始附件时，需要从仍保留的本地资料或确实可用的 CI 构建产物恢复到记录中的路径，并核对已有摘要。没有附件时应明确标记未核验，不把文件缺失当成视觉验收通过。这里不承诺旧 CI 附件仍在保留期内，也没有另行发布公共附件归档。

Linux 对照清单可在没有截图时生成库存报告：

```sh
python3 platforms/linux/validation/visual_inventory.py --output /tmp/xsime-visual-inventory.json
```

恢复本地图片后，加 `--require-assets` 检查所有对照附件是否存在；该检查与摘要计算不代替像素审查或真实宿主验收。

此次清理只取消当前文件的 Git 跟踪，保留本地附件，不重写已有提交历史。
