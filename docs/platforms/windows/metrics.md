# Windows 内置扩展与插件管理

Windows 设置沿用 macOS 的宿主划分：Buffer、Capsule、Mailbox 是三个同级宿主；并击、打字测速和统计是内置扩展。插件页用同一套三列橱窗卡片展示四类插件，支持“全部”和分类筛选、详情、设置、安装、启停和允许卸载的插件卸载。启停即时生效，停用保留记录，导航同步隐藏停用的内置扩展。

打字测速和统计由 `OfficialPlugins` 的固定版本包声明，通过同一个 `OfficialPluginStore` 验证身份、摘要、贡献类型和授权。原生实现从 `OfficialPlugins/native/windows/metrics*` 导入，随宿主编译；不加载任意 DLL。卸载、停用和重新启用通过插件注册记录管理，禁用后宿主不再采集对应数据。橱窗不维护第二套启用状态。

## 对齐内容

- 打字测速：macOS 的八篇原文与版本、随机选文、首次挑战和同篇重练、原生组字输入区、实时逐字反馈、有效速度、物理击键、回退、并击、过程和最终正确率、速度曲线、按文章及输入环境分组的历史成绩。
- 统计：每日、历史、测速成绩三个分页；7/30 天成文字数与日常速度、键位热图、全部记录年份的按键日历、日期选择和输入会话。统计与测速页共用成绩库。
- 四套现有主题、统一的间距、圆角、开关、选项框、键盘焦点、垂直滚动与 DPI 缩放。插件页的卡片名称和宿主分类沿用 macOS。

## 计数边界

Broker 只在实际按键通过隐私检查后发送汇总事件，`OnTestKey*` 不计数。成文字数来自引擎实际提交，并击次数来自一次真实并击结算。没有全局键盘钩子，没有读取外部输入框文本，也不保存按键时间线或输入内容。

测速只观察自己的 RichEdit 输入区。TSF/IMM 组字期间不进行成文评分；结束组字后再对齐。Windows ICU 字素分段及 NFC 比较对应 Swift Character 的字符语义。物理重复键单独记录；组字回退和成文回退分开，删除字符和纠正操作分开。计时从首次实际输入或组字开始，包含思考时间；未开始的空白练习不生成成绩。

外部宿主没有发送的并击信息显示不可用。失焦、换输入源、配置变化、粘贴/拖入、未完成文章等保留为练习，不混入有效成绩。自己的练习输入不进入日常统计；局部编辑器与 Broker 事件以虚拟键、消息时间及重复标记去重。日常活跃时长只累计相隔不超过 10 秒的输入。

## 本机记录

`%LOCALAPPDATA%\RIMES\metrics-v1\metrics.json` 只保存汇总计数、文章标识、输入环境和有界速度采样。按键分布和输入趋势可独立关闭、独立清空。默认值跟随 macOS，停用和卸载不会删除历史。

统计目录限制为当前用户和 SYSTEM，拒绝重解析路径，先写临时文件再原子替换。JSON 编码和文件写入不持有输入计数锁。文件限 4 MiB，最多 500 份成绩、500 个日常会话、120 个测速采样点；单篇练习最多 2048 个字素。读取会验证类型、范围及计数关系。损坏文件保持原样并进入只读状态，用户可在界面明确选择备份并重建。

## 验证与更新

先在官方插件仓库修改原生实现，运行 `scripts/generate_windows_articles.py --check`，提交依赖源码后运行主仓库 `scripts/prepare-official-plugins.py --update-lock`。不得用未提交的依赖内容伪造锁文件。

Windows 的 `RimesMetrics`、`RimesOfficialPlugins`、`RimesSettingsUi`、`RimesRuntime`、`RimesFirstKey` 和 `RimesChordProfile` 覆盖计数、持久化、插件授权、导航及输入通路。`RimesMetricsUiTests <目录>` 使用隔离的本机数据和自己的原生窗口，验证真实控件、同文替换、练习排除、启停、文章切换，并导出四主题的页面 PNG；不会向用户应用输入内容。

安装采用并列版本目录，保留词库、配置、插件状态与统计。Broker 重启后设置界面生效；已经加载旧 TSF DLL 的应用需要完全退出并重新打开。Codex 中的实际并击首字仍需要在新宿主进程中进行人工复测。
