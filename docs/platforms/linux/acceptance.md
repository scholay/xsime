## 桌面环境与跨模块检查

在 GNOME X11、GNOME Wayland、KDE X11、KDE Wayland 和目标 wlroots 桌面分别记录发行版、桌面版本、会话类型、显卡、显示器与缩放、Fcitx/GTK/Qt IM module 版本、宿主版本、源码提交和 deb SHA-256。至少覆盖两个发行版，以及 GTK、Qt、Firefox、Chromium/Electron、终端和 LibreOffice。

使用独立的公开测试档案和临时用户目录，保留个人词库与学习记录。与 stock `fcitx5-rime` 共存时，确认 XSIME 是独立输入法，`~/.local/share/rimes` 与 `~/.local/share/fcitx5/rime` 不互相覆盖。

1. 各模块经历锁屏、睡眠、切换用户、Fcitx 重启、UI 崩溃、跨屏拖动和 100%/150%/200% 缩放，检查窗口、草稿和焦点状态。
2. 重新聚焦、重新启动或解除保护后，旧投递目标和在途结果不能自动获得授权。密码字段不得被普通输入之外的捕获功能读取。
3. 在其他输入法中测试全局快捷键和桌面启动入口；检查 X11 冲突提示、Wayland portal 同意/拒绝/取消，以及快捷键录制期间暂停与恢复。
4. 分别测试 layer-shell、XWayland 回退及由合成器控制位置的窗口；记录实际支持边界，不将一种桌面的定位结果推广到另一种。
5. 检查缺失组件、插件停用、网络失败和取消操作的可见状态。普通输入不得被后台下载、AI 请求或设置窗口阻塞。

快捷键和启动方式见 [Linux IME 使用说明](../../../platforms/linux/ime/README.md#desktop-launch-and-global-shortcuts)。安装、升级、重装与卸载另按 [发布生命周期](release-lifecycle.md) 验证。

## 普通输入

对每个宿主分别执行：

1. 选择 XSIME 的雾凇全拼，输入 `nihao`，确认预编辑和候选；按空格后得到 `你好`，没有残留原码或重复成文。
2. 输入 `ni` 后按数字选非首候选；用多页候选测试左右、上下、PageUp/PageDown、候选矩阵及鼠标选择；Escape 取消时不提交文字。
3. 在已启用的全拼、双拼、五笔和英文方案中分别输入。测试 Shift 中英切换、空闲数字/空格、快捷键、长按和按键释放。
4. 未结束组字时切换输入框、宿主或输入法，再返回输入；不得留下重复预编辑、丢失首键或向旧输入框提交。
5. 在 GTK、Qt、浏览器密码框中记录输入法是否启用及实际保护行为；不能仅凭某一 toolkit 的标志推断所有密码框安全。
6. 使用新的隔离用户目录模拟首次部署，部署中立即输入和切换其他输入法。Fcitx 与远程控制保持响应；部署完成后无需重启即可输入中文。再检查部署中退出、下次启动恢复和用户目录锁。
7. 保存方案偏好后验证只影响目标方案，在空组字边界生效；恢复继承不删除用户自有设置，导入或卸载方案不损坏学习记录。

GNOME/KDE 的 GTK、Qt、Wayland、XWayland 路径分别记录。需要 `GTK_IM_MODULE=fcitx` 的宿主应在实际桌面会话中配置并复测；Shell 环境中的成功不能代表桌面启动成功。

## Buffer

行为基准见 [Buffer 规范](buffer-spec.md)。每个宿主先验证 Buffer 隐藏时普通输入正常，再执行：

1. 用当前快捷键打开 Buffer。宿主保留键盘焦点；输入 `nihao`、`shijie` 并选词，两次 Rime 提交成为两个块，宿主字段保持不变。
2. 用当前发送键或纸飞机发送一块，剩余块保留，不向宿主多送回车。按设置的长按阈值发送全部，继续按住或释放修饰键不得重复发送。
3. 组字中的发送按键先按当前方案语义结束组字，同一次按键不能再投递块；分别测试退格、Escape、关闭、恢复和最后一块后关闭。
4. 切换到另一窗口或同一网页的另一输入框后，捕获和投递立即失效。后续键入属于新宿主；重新唤起前不得向新字段发送旧块，也不得插入 U+200B 或吞掉 Escape。
5. 进入密码框、锁屏或停用插件时检查隐藏/撤权；从保护态恢复不会自动继承旧目标。宿主禁用输入法时也要检查 Escape、Return 和预编辑不泄漏。
6. 在 X11 测试候选附近放置、屏幕边缘、拖动、极小位移和按住鼠标静止；在 Wayland 测试底栏、缩放及定位降级。窗口不抢焦点，候选和块保持可读。
7. 在隔离会话终止 Buffer UI，等待恢复后只存在一个面板，普通输入继续工作。关闭原宿主后不得再向其他窗口发送。
8. 对启用的翻译/AI adapter 测试增量翻译、编辑、替代结果、取消、失败、返回编辑、复制、自动发送及源块消费。切换字段、渠道、配置或插件后，晚到结果不得重新显示或投递。
9. UI 重启或生成失败保留仍有效的原文；只有准备完成的结果可复制或发送。真实服务测试与本地假服务、离屏渲染分开记录。

### X11 drag-release timing (#44)

在 X11 + xfwm4 + Firefox 的同页两个文本框中，用第一个字段捕获公开样例，拖动工具栏约 80 px，然后释放鼠标并点击第二个字段。

| 物理释放后名义延迟 | 次数 | 必须检查 |
| --- | --- | --- |
| 0、5、10 ms | 每档至少 30 次 | 点击暂停捕获，下一次输入进入第二个字段 |
| 30、50、100 ms | 每档至少 10 次 | 无残留拖动状态、丢块或串投 |

记录实际释放、点击和 IPC 到达时序，不只记录 sleep 参数。区分 `drag_end` 在字段激活之前/之后到达；前者必须撤销捕获，后者单列物理释放竞态结果。日志只记录事件，不记录用户正文。另测按住鼠标停顿 2 秒/5 秒及约 3 px 的小拖动：拖动中的窗口管理器焦点回归不应误撤权，真正切换字段必须撤权。

`rimes-buffer-fcitx-e2e` 的命令顺序检查不能替代这组物理指针测试，较长延迟成功也不能代表 0–10 ms 成功。Wayland layer-shell 的拖动支持独立记录。

## Capsule

功能用法见 [Capsule README](../../../platforms/linux/capsule/README.md)，授权规则见 [Capsule 规范](capsule-spec.md)。

1. 用公开样例测试临时、捕获、笔记、资源、密码五模块的启停、筛选、搜索和导航。停用撤销在途操作与投递授权，磁盘内容保留。
2. 打开底栏时宿主不失去焦点。文本经原输入框的 Fcitx 提交；单击选择与双击使用分开测试，成功后关闭且无额外回车。切换字段或退出宿主后必须重新绑定。
3. Escape、搜索、Tab 和复制只在有效捕获时消费；解绑后正常交给宿主。Buffer 与 Capsule 同时存在时，确认输入所有权和发送目标无歧义。
4. 从底栏进入管理页编辑普通、Bullet、富文本笔记；检查 Ctrl+S、Esc、未保存修改确认、搜索保留草稿，以及外部修改后的修订冲突。管理页及返回底栏不能继承投递目标。
5. 显式复制改变剪贴板，查询、快照、重启及恢复不重放复制。以外部 sentinel 值检查 UI 重启、密码框和键盘复制；富媒体恢复原 MIME，不模拟粘贴。
6. 分别测试 X11/Wayland 剪贴板历史启用、基线、保护态、搜索、收藏、删除和容量提示；关闭收录后不得继续观察剪贴板。
7. 测试文件与资源引用、文献元数据、预览、附件副本及损坏文件处理。删除或卸载不能清除其他模块或用户自有文件。
8. 截图/录屏 portal 的同意、拒绝、取消、停止、会话关闭和锁屏分别验证；检查输出可解码和临时文件清理。缺少 DMA-BUF 等环境限制必须单列，不能记为完整录屏通过。
9. 密码库仅使用测试秘密，检查解锁、自动锁定、复制排除、TOTP、保护态和异常恢复；不得把真实秘密写入截图、日志或测试档案。
10. 终止隔离 Capsule UI 后只恢复一个底栏，普通输入和其他组件不受影响。检查多屏、不同窗口大小、缩放、键盘焦点及主题。

## Mailbox 与连接器

按 [Mailbox 使用说明](../../../platforms/linux/mailbox/README.md) 和 [连接器说明](../../../platforms/linux/runtime/README.md) 验证：

- 收件审核、附件到 Capsule/Buffer、复制、取消和重复收取；没有审核的内容不能自动上屏或获得输入目标。
- 同一会话续聊、固定渠道/模型、流式预览、失败重试、切换会话和撤权；旧请求不得写入新会话。
- 真实 PTY 输入、进程退出/取消、文件打开和手动成果收取；文件与会话身份对应，普通终端操作不隐式进入 Buffer。
- 本地 HTTP/MCP 网关的授权、关闭、超时、无效请求和未完成流清理；认证成功不等于允许直接投递。
- 官方 CLI 安装与登录检查、实际账号生成和原生控件分别记录；假服务、协议探针或登录成功都不代替真实生成验收。

## 并击、统计与打字练习

- 并击检查单键、同时按键、跨批配对、释放、取消、焦点切换、方案/键位修改及学习进度；不能由顺序按键探针代替物理并击。
- 统计检查启停、保护字段排除、聚合口径、导出/清理、损坏文件只读和重启保留；不得保存输入正文。
- 打字练习检查预编辑不评分、首次成文计时、回退/纠错、并击、粘贴/中断、同篇重练、成绩历史及日常统计隔离；移除素材不删除已有成绩。

## 视觉附件与验证命令

先按 [IME 构建说明](../../../platforms/linux/ime/README.md) 准备产物和共享数据。产品构建与自动回归走远端 CI；实际桌面检查记录对应产物。以下宿主测试只在隔离的 D-Bus 会话、测试显示器和临时档案中输入公开样例：

```sh
dbus-run-session --config-file=platforms/linux/ime/tests/portal_fixture_bus.conf -- \
  xvfb-run -a python3 platforms/linux/ime/tests/e2e/desktop_hosts.py \
  platforms/linux/ime/build /path/to/staged-data /tmp/xsime-desktop-results \
  --firefox /path/to/firefox
```

需要 `xdotool`、`xfwm4`、GTK/Qt Fcitx IM module 和 `xterm`；未提供 Firefox 时记为 `not_run`。该测试会话不自动启动 portal；真正的剪贴板和捕获 portal 测试另行执行。任何 `not_run`、warning 或降级都要单列，Xvfb/headless 成功不能替代实际桌面验收。

按 [视觉合同](visual-parity.md) 使用同一主题、样例、尺寸、缩放和状态对照两端。截图与日志保存在本地，清单中的历史状态不代表当前构建或当前附件已经验证。

```sh
python3 platforms/linux/validation/visual_inventory.py \
  --output /tmp/xsime-visual-inventory.json
```

默认命令支持无截图的干净检出，逐页区分 `manifest_only`、`partial_local_assets`、`complete_local_assets`；缺失附件记为 `missing_local`，没有摘要。对现存本地普通文件计算 SHA-256，`statusCounts` 仅转录历史状态。需要完整附件时，在清单所列原路径恢复截图，再运行：

```sh
python3 platforms/linux/validation/visual_inventory.py --require-assets \
  --output /tmp/xsime-visual-inventory-with-assets.json
```

严格模式缺图即失败，所有模式拒绝非本地路径、符号链接和非普通文件。生成库存报告或计算摘要不等于核对历史摘要，更不等于像素、人工审查或产品测试通过。
