# Linux 与 macOS 视觉、行为对齐

Linux 的组件样式及设置、管理界面以 macOS 原生实现为视觉基准。对当前支持的功能逐项检查布局、控件和交互，未实现功能不计为已完成验收。

## 基准

以当前 macOS 原生产品及其可复现渲染入口为准，不以旧 React 原型或 GTK 默认主题为准。记录两端对应的源码提交；基线变化后更新两端样例。

- `Sources/RimeBuffer/RimeUI.swift`：实际语义色、尺寸、字号、交互密度。
- `SettingsWindow.swift`、`SettingsRouting.swift`：980×680 设置窗口，160 侧栏及同序路由、子页面、三列插件卡、两列主题卡。
- `BufferWindowController.swift`、`BufferInlineView.swift`、`WorkbenchBarView.swift`：760 标准宽度、30 工具栏与 1 分隔线、2 外边距、73/105 高度、520–1100 宽度范围、源轨/结果轨、块下划线、状态与投递按钮。
- `RimeFixedAccentSwitch.swift`：Buffer 紧凑开关的 26×15 轨道、28×17 控件、旋钮、颜色与按下状态；折叠内容后保留 35 高的工具栏。
- `CapsuleWindowController.swift`、`CapsuleRailDetailView.swift`：五模块管理页、详情和底栏。
- `Mailbox/`：收件、对话、终端、会话和附件预览。

## 实现与证据

1. 先从原生源码提取布局和主题参数，再实现 Linux 原生界面。共享参数由脚本生成；禁止悄悄复制后独立漂移。
2. 相同固定数据、主题、逻辑尺寸、缩放和状态，分别通过实际 macOS 与 Linux 渲染路径输出图片。无私人笔记、凭据或聊天记录进入样例。
3. 每个界面记录尺寸/布局断言、两端截图、并排图、像素差异图与差异范围。覆盖正常、空、加载、错误、停用、选中、悬停、焦点、保护态和恢复。
4. 字体抗锯齿、字形和合成器材质等平台差异单列，不把它们用于掩盖尺寸、布局或交互错误。未经过对照的页面不能标记视觉验收完成。
5. 同一组行为样例验证启停、异步取消、状态迁移、源消费、投递成功/失败、跨模块流转。视觉验收与业务验收分别记录。

实际桌面检查见 [验收清单](acceptance.md)，安装包检查见 [发布生命周期](release-lifecycle.md)。截图和详细日志保留在本地，清单与结果摘要明确对应提交和平台。
