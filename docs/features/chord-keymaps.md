# 并击键位方案

并击扩展使用一套统一规则，既支持同批组键，也支持先左后右分开敲；飞耀是其中的内置键位方案。用户可以复制飞耀、新建方案，或导入其他用户导出的 JSON 键位文件，用可视化键盘和映射表编辑，不需要编写 Rime YAML，也不需要切换组键模式。

## 使用流程

1. 在设置中启用「并击」扩展，再进入「键位方案」页。启用扩展不会自动替换当前普通输入方案。
2. 选择「飞耀输入」查看内置映射；要修改它，先复制。也可选择「新建」或「导入…」创建独立方案。
3. 设置名称、左右键区、音节边界策略与输出编码，在可视化键盘上点选组合，填写输出拼音，并选择「完整音节」或「拼音片段」。映射表支持查找、添加、更新和删除。
4. 点击「试译和弦」，或在「本地试打」中点击「开始试打」后按键，查看当前草稿的映射结果。试打区域在一组键全部松开时结算，只展示本机结果，不调用 Rime 组字、不向外部输入框提交文字。正式输入的分批仍遵循扩展「设置」页的组键间隔。
5. 点击「保存草稿」保存编辑；点击「应用键位方案」才会部署并生效。应用按钮也会先保存当前编辑，再校验、部署和验证整个映射表。空映射表可以作为草稿保存，但不能应用。
6. 如果普通输入当前已经使用并击，应用后会切到新并击方案。如果当前使用雾凇全拼、双拼等普通方案，其选择保持不变；需要时在并击「设置」页点击「设为当前输入方案」。扩展开启的意识流使用已应用的键位方案，不要求普通输入也选中它。

「导出…」保存原生 JSON 文件。导入总是分配新的方案 ID，包括导入飞耀模板或本机已有方案的导出文件，因此不会覆盖同 ID 的现有草稿。导入成功后仍需保存、应用。内置飞耀不能覆盖或删除；正在使用的自定义方案也须先切换到其他方案才可删除。

## 键位与输出规则

| 项目 | 规则 |
| --- | --- |
| 参与键 | 仅小写 `a–z`、`,`、`.`；每个键最多属于一个键区，可只启用其中一部分 |
| 单键批次 | 单字母保留原字符，不允许通过映射表改写；单独的逗号／句号在普通输入中继续由 Rime 标点处理，在意识流并击解码中忽略 |
| 多键映射 | 至少两个不同的参与键；组合按键集合匹配，`dv` 与 `vd` 视为同一条，不能重复配置 |
| 输出 | 1–32 个小写 ASCII 字母，`ü` 写作 `v`；本版面向拼音片段／音节，不接受文字宏、命令或脚本 |
| 完整音节 | 使用「按映射类型」策略时，普通输入为它保留隔音符边界；意识流追加可继续编辑的软空格 |
| 拼音片段 | 使用「按映射类型」策略时不自动补边界，可继续补全；是否跨左右区不能代替这个显式类型 |
| 未配置组合 | 自定义方案按左键区再右键区顺序保留其中字母，消费多键组合里的逗号／句号；纯逗号加句号的未配置组合不产生文本，单个标点键按上述单键规则处理 |
| 规模 | 最多 4096 条映射、128 个自定义方案，单个文件不超过 2 MiB；名称 1–80 字符且 UTF-8 不超过 240 字节，不含换行／控制字符 |

并击先按「组键间隔」结算每一批按键，也允许左区批次与紧接着的右区批次重组，且至少一批为多键。跨批重组优先查合并后的整组键集合映射，不是盲目拼接两段输出。例如飞耀的 `dv` → `n`、`km` → `ong`，先左后右输入时使用 `dvkm` → `nong` 的整组映射。两次单键不会跨批合并。

跨批配对要求原输入、光标／选择、焦点及方案等快照仍然一致。「按映射类型」策略还要求合并键集合明确映射为「完整音节」；分隔符、编辑、焦点切换、方案应用等状态边界会撤销待配对批次。单纯停顿不会撤销配对，组键间隔也不是左右配对的超时。

音节边界策略与映射类型分别保存。新建方案默认「按映射类型（完整音节／片段）」；飞耀使用「每个多键批次（兼容飞耀）」，复制飞耀时也保留该策略。因此复制后的普通输入仍保留原来的多键批次隔音规则与跨批重组行为，不会因名称或身份改变而改变打字节奏。边界策略用于控制音节分隔，不是另一种组键模式。意识流始终按映射的完整音节／片段类型处理软空格。飞耀内置方案还保留既有 `my_combo` 的兼容性与学习进度。

## 输出编码：全拼与自然码双拼

每个自定义方案都有「输出编码」，可选「全拼」（默认）或「自然码双拼」。映射表始终按全拼填写，编码只在应用方案、生成 schema 时起作用，所以学习进度、意识流和编辑器读到的仍是全拼。内置飞耀只能使用全拼；要换成自然码，先复制飞耀，再在副本上切换。

全拼输出长短不一，两个音节连在一起时常能切成多种读法（`xi` 和 `an` 连起来的 `xian` 也可以是一个音节），只能靠隔音符区分，隔音符在插入、回退或编辑中丢失时就会选错字。自然码下每个完整音节固定两个键，边界由位置决定：隔音符丢了，`xian` 也只能读作 `xi'an`。

| 映射类型 | 编码规则 | 例子 |
| --- | --- | --- |
| 完整音节 | 按自然码布局编成两个键，与 `double_pinyin` 方案的拼写规则一致 | `zhang` → `vh`、`shui` → `uv`、`xiong` → `xs`、`lve` → `lt` |
| 零声母音节 | 自然码的零声母写法 | `a` → `aa`、`e` → `ee`、`o` → `oo`、`ang` → `ah`、`eng` → `eg`、`ai` → `ai` |
| 声母片段 | 一个键，`zh` / `ch` / `sh` 为 `v` / `i` / `u` | `sh` → `u`、`y` → `y` |
| 韵母片段 | 一个键，即补全音节的那个韵母键 | `iu` → `q`、`uan` → `r`、`ong` → `s`、`en` → `f` |

保存和应用时会校验每条输出：「完整音节」必须是合法拼音音节，「拼音片段」必须是声母或韵母，否则拒绝并指出是第几条。

生成的自然码 schema 与全拼版的差别：

- 拼写规则换成自然码代数，棱镜名为 `rimes_chord_ziranma`；词库仍是 `rime_ice`，用户词频两种编码共用。
- 输入区经 `preedit_format` 显示全拼，Rime 内部保存的是双拼码。
- 不启用简拼：只打声母的缩写会重新带来长短不一的切分。
- 雾凇的日期类触发码改为 `date` / `time` / `week` / `datetime` / `timestamp` / `lunar`，与 `double_pinyin` 方案相同；原来的 `ts` / `sj` / `xq` / `nl` 在自然码里是「同、三、修、奶」的编码。
- 自定义短语与中英混合词分别使用 `custom_phrase_double` 和 `en_dicts/cn_en_double_pinyin`；雾凇的候选置顶照常生效，因为它匹配的是显示出来的全拼。

改用自然码后需要注意：

- 单键仍然原样输入，但字母按自然码解释（例如 `u` 表示 `sh`）。
- 单独按下右手韵母片段得到的是韵母键，不再单独出「嗯、欧」这类零声母字，请用映射表里的零声母组合。
- 意识流仍按映射表的全拼输出解码并击。

### 仓库里的方案文件

`chord-keymaps/` 收有两份可直接导入的方案，都由飞耀映射表复制而来，保留「每个多键批次（兼容飞耀）」边界策略：

| 文件 | 输出编码 | 说明 |
| --- | --- | --- |
| `chord-keymaps/Isaac2025.json` | 全拼 | 飞耀全拼映射的冻结备份 |
| `chord-keymaps/Isaac2026.json` | 自然码双拼 | 同一张映射表，按自然码编码 |

在「键位方案」页点「导入…」选择文件，保存后点「应用键位方案」即可。导入会分配新的方案 ID，不会覆盖本机已有的同名方案。

## 原生并击方案：呦呦音形

「键位方案」列表在飞耀之后还有两个原生并击方案：「呦呦音形 · 折梅」（`yoyo-yx`）和「呦呦音形 · 寒梅」（`yoyo-yx-hm`），来自麓鸣输入法的音形分支。它们不是键位映射表：180 个码元、四条输入通道、一简和顶功都由方案自己的 Rime 配置、字典和 Lua 处理器定义，规则见[呦呦音形介绍页](https://rayalizing.github.io/yoyo/#/yinxing)。在列表中选中后点「应用键位方案」即可，和其他方案一样会部署并验证；两个方案共用字词表，切换时各自重建词典，约需 10–20 秒。

原生方案在 RIMES 里只读，不能编辑、复制或导入为自定义键位。与飞耀类方案的区别：

- **按全部松开结算。** 每个按键的按下和松开都直接交给 librime 的 chord_composer，一组键在最后一个键松开时结算，与 Squirrel 和麓鸣练习器一致；组键间隔设置不参与原生方案。按住不放不会重复按键。
- **空格、数字行和 `- = [ ;` 都是并击键**（两种指法共用这张字母表，寒梅另加 `/`，只是寒梅的指法用不到数字行和 `- = [`），所以方案启用时这些键不再用于候选窗选择；二选、翻页按方案自己的绑定（`'` 二选，Tab / Shift+Tab 翻页）。按住 Shift、Control、Option 或 Command 的按键仍走普通路径。
- **漏掉的松开会被补上。** 焦点切换、非并击键打断，或宿主应用没有送来松开事件时，RIMES 会替仍按住的键补发松开，避免下一组并击夹带旧键；如果这组键结算时原输入框已经失去焦点，结果会被丢弃，不会上屏到别处。
- 飞耀学习页不提供原生方案的课程；意识流输入在原生方案下使用逐字采集，不解码并击。

方案文件原样收录于 `rime-data/`，来源、校验和与授权状态见 `rime-data/licenses/yoyo-SOURCE.md`。

旧版「只结算同批」设置会自动迁移到这套统一并击规则：原有启用状态、当前方案、键位、组键间隔与学习进度保持不变，不再保留单独的模式开关。

## 原生文件格式

文件是 UTF-8 JSON，`formatVersion` 当前必须为 `1`。以下示例将左区 `dv` 映射为片段 `n`，右区 `km` 映射为片段 `ong`，整组 `dvkm` 映射为音节 `nong`。ID 在导入时会替换成新的 UUID。

```json
{
  "formatVersion": 1,
  "id": "44444444-4444-4444-8444-444444444444",
  "name": "我的并击方案",
  "leftKeys": "qwertasdfgzxcvb",
  "rightKeys": "yuiophjklnm,.",
  "boundaryPolicy": "explicitSyllables",
  "outputEncoding": "fullPinyin",
  "mappings": [
    { "keys": "dv", "output": "n", "kind": "fragment" },
    { "keys": "km", "output": "ong", "kind": "fragment" },
    { "keys": "dvkm", "output": "nong", "kind": "syllable" }
  ]
}
```

`boundaryPolicy` 可为 `explicitSyllables` 或 `legacyBatches`；旧版文件省略时按 `explicitSyllables` 处理。`outputEncoding` 可为 `fullPinyin` 或 `ziranma`；省略时按 `fullPinyin` 处理，映射里的 `output` 在两种编码下都写全拼。此导入入口只接受上述数据格式，不执行任意 Rime YAML、Lua、正则表达式或远程代码。已有 Rime 方案的自定义处理器与代数不能通过改扩展名导入；需要把所需键集合和最终拼音输出整理成映射。保存时会规范化键序，并拒绝未分区键、重复组合、非法输出与不支持的格式版本。

## 保存、应用与升级

默认持久目录为 `~/Library/RIMES/chord-keymaps/`，目录权限为 `0700`，原生数据文件采用原子写入并保持 `0600`：

```text
chord-keymaps/
├── <方案 UUID>.json       # 可继续编辑的已保存草稿
└── active-profile.json    # 最近成功应用的完整方案快照
```

`ChordKeymapStore` 分别管理草稿和已应用快照。修改并保存当前方案后，普通输入和意识流仍使用之前成功应用的内容；重启也不会把新草稿自动当作生效版本。应用过程冻结待部署内容，退出旧输入会话，生成适配 schema、部署并逐条验证映射，成功后才发布该快照；失败会恢复之前的方案文件与选择。快照损坏或恢复部署无法通过验证时，暂停并击、退回普通输入，并在输入方案页显示恢复提示；原文件保留，不会偷偷启用较新的草稿。

飞耀模板读取有效 `my_combo` 配置，保留既有方案兼容性。自定义方案生成 `rimes_chord_<去掉连字符的 UUID>.schema.yaml`，沿用雾凇拼音的候选、词库和翻译链；自然码方案另换拼写规则与棱镜，见上文「输出编码」。生成文件属于可重建的部署产物，原生 JSON 才是自定义键位的持久数据。生成器先把所有组合映射到临时标记，最后统一展开拼音，防止输出再次命中其他组合而发生二次映射。

开发安装的 Rime 数据重新播种会保留整个 `chord-keymaps` 目录及文件权限；从 Squirrel 导入配置也会排除其同名目录，不能覆盖本机键位状态。下次启动可从已应用快照重建自定义 schema。键位数据只保存在本机；迁移到另一台电脑使用显式导出／导入。

## 验证入口

- `RimeBuffer chord-unification-smoke`：唯一并击运行策略、旧设置迁移、读取顺序与重启一致性，以及启用状态、普通方案、间隔和键位数据保留。
- `RimeBuffer chord-keymap-smoke`：数据格式、重复组合、原生导入、权限、草稿与生效快照分离，以及编译后的组合排列与二次映射检查。
- `RimeBuffer chord-keymap-ui-smoke [输出.png]`：实际编辑器控件、草稿保存、独立试译和 AppKit 布局渲染。
- `RimeBuffer chord-settings-smoke [输出.png]`：统一并击设置文案、无旧模式选择器、组键间隔和方案选择的隔离控件测试，以及 AppKit 布局渲染。
- `RimeBuffer chord-keymap-activation-smoke`：应用事务、部署及持久化故障注入、恢复与并发门控。
- `RimeBuffer chord-keymap-engine-smoke`：在隔离的真实 librime 中验证生成方案、全部飞耀映射、音节边界、中文候选和重新部署恢复；开发环境需先备齐 `Vendor/rime`。
- `RimeBuffer native-chord-smoke`：原生方案的按键路由、按住键记录与漏掉松开的补发、预设只读与解析、激活只启用内置 schema、飞耀暂存与意识流并击的门控。
- `RimeBuffer yoyo-engine-smoke`：在隔离的真实 librime 中通过键位方案激活流程依次部署折梅与寒梅，逐一核对介绍页公开的一简字词、单字与词的并击结果，并验证只松开部分键时不会结算。
- `RimeBuffer chord-ziranma-smoke`：全拼到自然码的转换（对照自然码布局逐项写出的期望码）、音节表撞码检查（只允许 ü 的两种写法同码，以及自然码本身让 `lo` 与 `luo` 同码）、飞耀全部映射可转换、`outputEncoding` 读写与旧文件兼容、生成的 schema 与编辑器试译。
- `RimeBuffer chord-ziranma-engine-smoke [报告目录]`：在隔离的真实 librime 中分别部署飞耀的全拼和自然码副本，逐条核对每个和弦的原码、全拼显示与首页候选，并验证隔音符位置和无隔音符连打；给出目录时写出两份方案 JSON 和逐条对照表。
- `bash scripts/test-rime-user-state.sh`：用临时目录核验安装重新播种／导入对键位草稿、已应用快照、字节内容与权限的保留。

引擎部署与映射验证使用独立 Rime 会话；自动化 smoke 的 Rime 用户目录必须隔离，不能打开正在运行的输入法词库。
